# Plans

A plan lives here when the work is too large or too contested to state as an
issue — a network dependency, a design sweep, anything with open questions that
have to be answered before a branch is worth opening.

Lifecycle: draft here → the issue in
[issues/upcoming/](../issues/upcoming/) points at it → the work lands in numbered
phases → the phase records go to [issues/done/](../issues/done/) and the durable
parts move into [knowledge/](../knowledge/). A plan that has fully landed is
deleted; git holds it.

**Record where the build disagreed with the plan** rather than quietly rewriting
it. The reasoning that turned out to be wrong is the useful part.
